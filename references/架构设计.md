> 版本：v1.0  |  适用范围：agent-flow-visualizer 生成的所有项目

## 一、设计哲学

**单 Agent 和多 Agent 不是两种模式，而是同一个架构的不同实例。**

```
单 Agent = DAG 只有 1 个节点，内部是线性循环
多 Agent = DAG 有 N 个节点，节点间可委托 / 并行 / 汇总

统一架构：多 Agent DAG 引擎
```

## 三、核心数据流

```
用户输入
   │
   ↓
AgentScheduler.run(userPrompt)
   │
   ↓ 从 dag.entryAgentId 开始
executeAgent(agentId, task)
   │
   ├── while status !== done:
   │     │
   │     ├── LLMClient.callLLM(messages, tools)
   │     │     → 返回 { text, toolCalls? }
   │     │
   │     ├── 如果有 toolCalls:
   │     │     for each toolCall:
   │     │       ToolRegistry.get(name).execute(params, context)
   │     │       context.scheduler → agent_call 工具可以启动子 Agent
   │     │
   │     └── 如果无 toolCalls → status = done
   │
   ↓
返回 Agent 最终状态
```

## 四、LLM 对接

### 4.1 Mock 模式（默认）

骨架内置 mock LLMClient，模拟一个"思考 → 工具调用 → 结果"的循环，用于演示场景，不需要真实 API Key。

### 4.2 真实 API 模式

编辑 `src/core/LLMClient.ts` 的 `callLLM` 方法，替换为真实 API 调用。推荐使用 OpenAI 兼容协议，一次适配多家提供商：

```typescript
async function callLLM(
  messages: AgentMessage[],
  tools: AgentTool[],
  config: LLMConfig
): Promise<LLMResponse> {
  const response = await fetch(`${config.baseUrl}/chat/completions`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${config.apiKey}`,
    },
    body: JSON.stringify({
      model: config.model,
      messages: [...messages],
      tools: tools.map(t => ({
        type: "function",
        function: { name: t.name, description: t.description, parameters: t.parameters }
      })),
      stream: config.stream ?? true,
    }),
  });

  // 解析 SSE 流式响应，累积到 text 和 toolCalls
  return { text, toolCalls, usage };
}
```

### 4.3 提供商配置

| 提供商 | baseUrl | model 示例 |
|--------|---------|-----------|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Deepseek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 本地部署 (vLLM) | `http://localhost:8000/v1` | 实际部署模型名 |
| 任何 OpenAI 兼容 | 各自地址 | 各自模型名 |
